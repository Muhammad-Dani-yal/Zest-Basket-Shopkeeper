## Verification boundaries

- Production builds: backend TypeScript and frontend TypeScript/Vite checks are run through `npm.cmd run portal:build`.
- API/business/realtime tests: `npm.cmd test --prefix backend`.
- Frontend route/shared-state render tests: `npm.cmd test --prefix frontend`.
- Exact test counts and the final build/startup results are recorded in the delivery message after the final run.
- The API uses one serialized writer. Multi-process synchronization and Atlas transaction connectivity need deployment-environment testing.
- Multi-shop extra-fee and radius/batch utilities are tested; `/api/demo/multi-shop/quote` exposes a demo quote. Customer switch/drop approval is a tested business service, not a connected external customer portal. The shopkeeper cannot approve a customer decision or admin verification.
- Hero artwork is derived from the reference; fallback product/rider emoji and vector logo are approximations. Image fidelity has not been visually verified.
- PWA installation, print layout, CSV/PDF downloads through browser controls, responsive widths 320/390/430, keyboard focus, notifications across multiple browser tabs and real mobile performance still need browser/device QA.
